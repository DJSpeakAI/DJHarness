# @local/dsh-quote-menu — 划词菜单（问 AI / 引用）

选中聊天里的一段文字 → 弹出小菜单：

- **问 AI** —— 在页面上浮出一个**临时小浮窗**（不是新页面、不是真弹窗），
  顶上有模型选择（跟输入框右下角那个选择器**同一份目录**），后台自动把
  整段会话历史当上下文；问完可以接着追问，关掉即丢，**不写进主会话**。
- **引用** —— 把「这段文字 + 它出自哪里」带进「当前会话 / 新建会话」。
- **复制**（仅 PC 右键菜单）—— 右键被我们接管了，原生那份不再出现，补回来。

## 怎么用

**整页生效**：聊天区、设置弹窗、插件页、右栏文档预览、工具输出……只要有文字的地方，
选中就能用。**唯一让给浏览器的是输入框 / 编辑器**（`contenteditable`、`textarea`）——
那里右键还是原生的剪切/复制/粘贴，不然就没法编辑了；问 AI 小窗里选字也还给浏览器，
方便复制答案。

触发方式两端不同：

| 端 | 怎么唤出 |
|---|---|
| PC | 拖选文字后**什么都不弹**；**右键**才弹竖排小菜单 |
| 手机 | 双击选词或长按拖选，**直接弹**横排小胶囊 |

**第一段的按钮看你在哪选的字**：

| 选区位置 | PC 右键菜单 | 手机胶囊 |
|---|---|---|
| 聊天区里的消息 | `问 AI` / `引用` / `复制` | `问 AI` / `引用` |
| 其他任何地方（设置、插件页、文档…） | `问 AI` / `复制` | `问 AI` |

> 「引用」只在聊天区出现，因为它要标出处（引用自哪个会话、第几轮、谁说的）；
> 别处没有出处可标。**问 AI 到处都有**。
> PC 上为什么要给「复制」：右键菜单被我们接管了，原生那份不再出现，
> 不补一个复制就等于把它弄没了。手机上浏览器自己的选中菜单还在，所以不重复放。

**第二段**（点「引用」之后才展开）：`当前会话` / `新建会话`

- **当前会话** —— 插进当前输入框，一次插两样：
  - 第一行普通文字：`引用自《会话标题》· 第 N 轮 · AI`
  - 下面一个引用卡片：选中的原文（官方原子节点，可单独删、可跟正文一起发）
- **新建会话** —— 先 `fork`（= 分支，完整继承当前会话历史），再打开新会话，
  等它的输入框就绪后把同样的「出处 + 引用块」放进去，光标停在后面等你补充问题。

点空白处 / 滚动 / 按 Esc 都会收起菜单。

## 问 AI 小浮窗

### 交互

| 动作 | 结果 |
|---|---|
| 点右上角模型名 | 展开模型清单（按提供方分组，✓ 是当前用的那个） |
| Enter | 发送 |
| Shift + Enter | 换行 |
| 拖标题栏 | 挪窗口位置 |
| Esc / 点 ✕ | 关掉（正在回答时会先掐断请求） |
| 正在回答时的 `停止` | 掐断，已经出来的半截保留 |

- 窗口贴着鼠标/选区浮出，出界会自动翻到另一边并夹在视口内。
- 选中的原文显示在标题下面一条引用条里（只是给你看清楚抓到了什么，
  不用你手动贴进输入框）。
- 第一次提问会把「选中的原文」+「你的问题」一起发出去；后面追问只发你的问题。
- 关掉窗口 = 这次临时对话全部丢弃，主会话里**一个字都不会多**。

### 上下文怎么给的

Host 半边（`index.js`）在收到问题时现取：

1. `session.deriveMessages()` —— 取当前会话**模型可见的完整历史**；
2. 只保留 `user` / `assistant` 的**纯文本块**，丢掉 system、开发者提示、
   工具调用、工具结果（工具输出动辄几万字，塞进去又贵又没用）；
3. 从**最老的开始**丢，直到总量 ≤ 40 万字符（约 20 万 token），超了就只带最近的部分；
4. 把客户端那几轮临时对话接在后面；
5. `ctx.llm.stream()` 直连模型，**完全不碰会话日志**，所以主会话不被污染。

> 会话背景取的是「当前/最近打开过的那个会话」。如果整个页面生命周期里还没开过会话
> （比如刚打开就直接在插件页划词），那就只有你选中的那段原文，没有会话背景 ——
> 照样能问。

> 为什么上下文里可能"看不到"某些内容：如果当时的回答是模型在 reasoning（思考）里
> 说的、最终文本里没写，那这段就不在 `deriveMessages()` 的文本块里 ——
> 知识类问答（回答写在正文里）不受影响。

> Prompt 缓存：会话上下文放在最前面、临时对话接在后面，所以反复追问时
> 前缀不变，DeepSeek 那边能命中缓存，第二轮开始明显变快。

### 接口

| 接口 | 用途 |
|---|---|
| `POST /quote-menu-api/models` | 兜底模型清单（`llm.listProviders()` + `listModels()`）；正常情况下客户端走 `ctx.modelDirectories`，用不到它 |
| `POST /quote-menu-api/ask` | 流式回答，NDJSON 一行一个事件：`start` / `delta` / `usage` / `error` / `aborted` / `done` |

`/ask` 入参：`{ sessionId, provider, model, turns: [{role, text}] }`。

## 实现要点

- Client 纯 DOM（不走 React 渲染），因为要边流式追加边滚动；只用一个
  `conversation.input.dock` 的**不渲染任何 DOM** 的桥接组件拿 `inputActions` / `sessionId`。
- **不覆盖** `@deepseek-ai/dsh-message-quotes` 的注册；只用一条 CSS 把它的
  「引用文本」小胶囊藏掉，输入框里 QuoteNode 的渲染规则仍由官方提供。
- 两端分流靠 `pointerdown` 的 `pointerType`：`mouse` = PC（只认右键），`touch/pen` = 手机（选中即弹）。
- PC 右键在 **document 捕获阶段** `preventDefault + stopPropagation`，
  只在「选区非空、且不在可编辑元素 / 不在小窗里」时接管，其余位置照常走浏览器原生菜单。
  可编辑判定：`input` / `textarea` / `isContentEditable` 的祖先（`contenteditable="false"` 不算）。
- 模型清单读 `ctx.get('modelDirectories').directoryFor(sessionId).store` ——
  和 composer 那个选择器**同一个实例**，所以模型名、提供方分组、默认选择天然一致。
  只读不写：在小窗里换模型**不会**改会话本身的模型。
- 宿主返回的 assistant 历史必须带 `source`（deepseek 适配器读 `source.kind`），
  并且要丢掉 `replayState`（块已经被裁过，旧的重放信封对不上会报错）。
- 有状态的组件放在插件单例 `S` 里；样式在 `apply` 里用 `ctx.effect` 挂/摘。

## 已知限制

- `fork` 只能从**已完成的轮次**切出来。当前这轮还在回答时点「新建会话」，
  官方会回 `session/fork-unavailable: has no completed turn to fork from`，
  菜单提示「这轮还没答完」。
- **输入框 / 编辑器里选字不接管**（保留原生剪切/复制/粘贴）；小窗里选字也不接管（方便复制答案）。
- 问 AI 小窗**不支持发图片/文件**，也不能调工具 —— 它只是个「带着上下文问一句」的小窗。
- 会话特别长时第一次提问会慢（要重发一遍上下文）；追问因为有缓存会快很多。
- 设置弹窗是 `aria-modal` 的：小窗浮在它上面、能正常打字（实测焦点不被抢），
  但**按 Esc 只关小窗、不关设置**（Esc 被小窗吃掉了）。

## 卸载 / 回滚

插件页关掉「划词引用」，或 `plugin_manager` 移除 `@local/dsh-quote-menu`。
关掉后官方那颗「引用文本」小胶囊会立刻回来（CSS 是插件注入的，随插件一起消失）。

## 文件

- `client.js` —— 菜单、两段状态、选区判断、出处、fork、桥接组件、问 AI 小浮窗
- `index.js` —— Host 半边：模型清单 + 流式回答（`/quote-menu-api`）
- `cordis.patch.yml` —— `insert` 一行 `quote-menu`
